# 语义去重阈值怎么校准（`semanticThreshold`，当前 0.92）

> **状态：未校准。** 0.92 是 D6 拍板时定的**保守档初值**，不是量出来的。
> 至今没有任何一次真实数据验证过它准不准。本文是采集方案，不是结论。

按 `src/dedupe/semantic.js` 的定调，这个功能最贵的错误是**误合并**：
「误删你真收藏的内容在这个项目里是最贵的错误」。
所以整份方案围绕一件事——**把「不该合并」的最高分找出来**，阈值定在它之上。

---

## 0. 动手前必须先冻结的三件事

数据是围绕某个具体配置采的。配置一换，数据全部作废。

| 冻结项 | 当前值 | 为什么不能变 |
|---|---|---|
| embedding 模型与维度 | 百炼 `text-embedding-v4` / 1024 维 | 换模型后分数分布整体平移。`semantic-runner.js` 的 `clearVectors` 注释已经写明「换了模型或维度之后必须清，否则新旧向量混在一起比」——**校准数据同样作废** |
| 输入形态 | `buildEmbeddingText` = 标题 + **URL** + 正文摘要 300 字 | 见下面那条警告 |
| 候选空间 | `candidatePairs` 的粗筛结果 | 见 §2 |

> ⚠️ **两种输入形态要分别校准，不能共用一个阈值。**
> `buildEmbeddingText` 在有归档正文时是「标题 + URL + 300 字正文」，
> 没开归档侧车时退回「标题 + URL」。这是**两个不同的向量空间**，
> 分数分布不一样。用「只有标题」的数据定出的阈值，拿到「有正文」上必然偏松或偏紧。
> 报告结论时必须写清是哪种形态下测的。

> ⚠️ **URL 被拼进了 embedding 文本**（`buildEmbeddingText` 的 `parts` 里含 `item.url`）。
> 这有一个反直觉的后果：**镜像站的分数被 URL 里的域名差异往下拉**。
> 同一篇文章在 A 站和 B 站，向量里带着两个不同的域名串，正文再像也会被拖分。
> 如果校准发现「正样本分数普遍偏低、镜像站漏判很多」，第一个该试的是
> **把 URL 从 embedding 文本里去掉**（它对「是否同内容」几乎没有信息量，
> 反而引入了站点身份这个与任务无关的变量）。这是改 `buildEmbeddingText` 的事，
> 属于另一个工单，但校准数据会告诉你值不值得改。

## 1. ⚠️ 最容易糊弄过去的一步：负样本不能手写

**手写的负样本几乎必然是废的。**

800 条书签两两配对约 **32 万对**，其中绝大多数分数很低（讲不同事情的文章）。
你随机抽 50 对标一遍，49 对都是「一眼就不相关」的，标完你会得出
「阈值定 0.5 就够了，0.92 太保守」——**这个结论是错的**，
因为真正的决策边界在 0.88~0.95 那一小段，而随机抽样几乎必然错过它。

人写负样本时还有第二个偏差：会不自觉挑**明显不同**的
（不同国家、不同语言、不同领域），而模型对那些本来就给低分。
你等于没测到边界，却在边界上做了决定。

**所以负样本必须从真实数据里「挖」出来，按分数分带抽。** 见 §3。

## 2. 候选空间：校准发生在粗筛**之后**

`suggestMerges` 不比 32 万对，它先过 `candidatePairs(items)` 粗筛：

```js
if (hostOf(a.url) === hostOf(b.url) && !titleOverlap(a.title, b.title)) continue;
```

即：**只砍「同站 + 标题词级重合度 < 0.6」的对**。于是

- **跨站对全部放行**（含全部「镜像 / 转载 / 聚合页 vs 原文」——这正是语义去重的主战场）
- 同站对里，标题重合度 ≥0.6 的也放行

> ✅ 一个值得知道的结论：**最危险的那一类负样本恰好能穿过粗筛**。
> 「某博客 · 周刊第 300 期」与「第 301 期」——同站，但 2-gram 重合度约 0.89，
> 粗筛放行，于是它们**真的会去比 0.92 这个阈值**。
> 换句话说，风险最高的样本确实在阈值的作用范围内，校准是对症的。

校准的分带与抽样必须在这个**过滤后**的分布上做，不是全量 32 万对上做。
顺带说明：粗筛的判据是「零成本且不会错」的信号，它砍掉的都是真不可能同内容的对，
**校准不需要重新验证粗筛**。

## 3. 采集流程

### ① 跑一轮全量打分，**不设阈值**

现在的面板按 `semanticThreshold` 过滤后只显示达标的建议，看不到分布。
采集需要**全部候选对的分数**。

最省事的做法：把阈值临时设成 `0`（`suggestMerges` 的 `score >= threshold`，
设 0 则所有余弦非负的对全部通过），跑一轮，然后导出。
⚠️ 别忘了改回来。

> 面板目前**没有导出功能**。需要加一个「导出建议清单为 CSV」的小功能
> （顺带也是个正当的产品功能：用户想看被阈值藏起来的那些对）。
> 列：`score, titleA, urlA, titleB, urlB, sameSite, label`
> —— `label` 留空给标注用。

### ② 按分数**分带**抽样

对过滤后的全部分数排序，切成带，每带抽 8–10 对：

| 带 | 为什么抽 |
|---|---|
| ≥ 0.99 | 几乎必然是真重复。确认一下，顺便看有没有「分数极高但其实不同」的异常 |
| 0.95 – 0.99 | 真镜像多在这里。检查正样本是否够 |
| 0.92 – 0.95 | **当前阈值就在这条带里。** 最关键的一带 |
| 0.88 – 0.92 | 阈值下沿。这带里的负样本决定阈值能不能守住 |
| 0.82 – 0.88 | 观察负样本密度 |
| < 0.82 | 抽 2–3 对确认「确实不相关」即可，不用多花时间 |

**目标不是「标满 50 对」，是「拿到 ≥8 个标为『不是同一份内容』且分数 ≥0.88 的对」**。
拿不到这一组，说明数据不够，回到 ① 扩大范围。

### ③ 专门去挖「同主题不同内容」

分带抽样会捞到一些，但**不够**——这类对在真实书签里占比低。
必须主动构造/寻找，下面这些是最容易出事的形态：

| 类别 | 形态示例 | 为什么危险 |
|---|---|---|
| **同站连载/分期** | 某博客「第 300 期」与「第 301 期」 | 模板词面几乎一致，向量极近，内容完全不同。**本项目里最危险的一类** |
| 站点索引页 vs 具体页 | `example.com/blog` 与 `example.com/blog/2026/10/post` | 都是「列表 + 标题」结构同构 |
| 聚合页 vs 原文 | 某聚合站的转载页 vs 原始出处 | 标题里都含站点名 |
| 产品/版本系列 | 新旧两代同一产品的评测 | 系列词面一致，差异只在参数 |
| 文档不同版本 | 同 API 的 v1 与 v2 文档页 | 极近但不同，且是「用户真想都留着」的那类 |
| 同一作者不同作品 | 同作者两本书/两个库的详情页 | 模板 = 作者名 + 标题 |
| 分页 / 翻页 | 列表第 1 页与第 2 页 | 正文摘要几乎一样 |
| 同站不同栏目同主题 | 同站「前端」栏与「周刊」栏讲同一件事 | 同站 + 高标题重合，粗筛也放行 |

**找法**：按 host 分组找「同站且标题前缀高度重复」的簇（同连载、同作者、同产品线），
这是最高产的来源。

### ④ 标注

用导出的 CSV 填，`label` 三选一：`same` / `diff` / `unsure`。

> ⚠️ **判据必须是事实，不是相似度**：
> 问「**这两条点进去是同一份内容吗？**」
> **不要**问「这两条讲的是同一个主题吗？」——后者正是模型在做的事，
> 也是它出错的地方。用「同一个主题」当标注判据，等于拿模型的尺子量模型，
> 校准出来的是模型对自己的评价，不是事实。
>
> `unsure` 就标 `unsure`，**不要逼自己二选一**。模糊样本恰恰是阈值该保守对待的地方。
> 阈值取「`diff` 的最高分」，`unsure` 的最高分也应当**低于**阈值——
> 如果某个 `unsure` 的分数比所有 `diff` 都高，说明边界之外还有一片说不清的地带，
> 那本身就是要报告的结论。

**标注纪律**：
- 先标 20 对就停下来看一眼分布。方向反了（比如正负完全反序）立刻停，
  别等标完 50 对才发现。
- 记录**正负比**。目标是边界带里有正有负；某一带里全是正，说明这一带没有负样本，
  阈值下沿的约束就还是空的。
- ⚠️ **标注数据不许进版本库。** 仓库是 public（见 `AGENTS.md` 的 Issue tracker 一节），
  里面是真实书签标题与 URL。放 `.scratch/`（已 gitignore）或仓库外。
  `tools/privacy_gate.py` 会扫真书签数据，别绕过它。

## 4. 怎么用结果

**阈值 = 所有标为 `diff` 的对里，分数最高的那一个**（零容忍下界）。
`unsure` 的最高分应当也低于它。

| 观测 | 结论 | 动作 |
|---|---|---|
| 最高负样本分 ≤ 0.88 | 0.92 有余量 | **保持 0.92**，在报告里写下实测下界 |
| 最高负样本分 ∈ (0.88, 0.92] | 0.92 勉强守得住但贴边 | 保持但记录，或上调到下界之上留 0.02 |
| 最高负样本分 > 0.92 | **0.92 会误合并** | 上调阈值；先看是不是「URL 拼进 embedding 文本」拖的（见 §0） |
| 最高负样本分 < 0.80 | 0.92 过于保守，几乎永不触发 | 阈值形同虚设。但**这比误删安全**，报告结论为「功能实际未生效」而不是贸然下调 |
| 边界带里 `same` 与 `diff` 分数**完全重叠** | 这个模型在这个任务上分不开 | **阈值调不出来。** 要么换模型，要么改策略（例如只在「标题高度重合」时启用语义去重），要么承认这个功能在这份数据上没有价值 |

> 最后一行必须说清楚：**校准有可能得出「这个功能不该开」的结论，那也是一个有效结果。**
> 把它当成分配任务去做（必须给出数字），就一定会得出「阈值可以再松一点」这种
> 由任务本身决定了的答案。判据是「零误合并」，不是「找出最优阈值」。

## 5. 结论要记在哪

- 阈值本体写在 `src/storage.js` 的 `DEFAULT_SETTINGS.semanticThreshold`（代码里的唯一权威）。
- 实测结论（模型、输入形态、样本数、最高负样本分、最终取值）写回**本文**的「结果」小节。
- 面板上若展示该阈值，应同时说明它**是否已校准**——
  「界面承诺一件永远不会发生的事，比功能缺失更伤」（`AGENTS.md` 第 8 条）。
- 相关：`docs/acceptance-thresholds.md` 的阈值总表。
