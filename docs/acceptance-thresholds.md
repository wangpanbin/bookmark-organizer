# 验收阈值总表

代码里散落着一批「这个数字为什么是这个数字」。集中在这里，
**每个阈值都注明它的判据是什么、有没有被真实数据验证过**。

> ⚠️ 「未校准」这一栏是这张表存在的理由。
> 一个凭直觉定的数字和量出来的数字，写在代码里长得一模一样。
> 分不清就会有人拿它当依据做决定 —— 而它撑不住那个重量。

## 2. 链接健康（死链 / 改链）

| 阈值 | 值 | 判据 | 状态 |
|---|---|---|---|
| 死链 | **连续 3 次 404/410 且距上次成功 ≥24h** | 见下 | ✅ 判据有据 |
| 计入失败的 HTTP 码 | **仅 404 / 410** | 403（要登录）、429（限流）、5xx、**超时永不计入** | ✅ |
| 软 404 | 启发式，**只标不判**、**不计入失败计数** | 特征串匹配一定会误伤一篇讲「HTTP 404 怎么排查」的文章 | ✅ |
| 单条探测超时 | 8000 ms | 再长会让一轮拖到天亮 | ⚠️ **无 UI**，改它要编辑 storage | 
| 并发上限 | 6 | 保守值。**不要调高** —— 再高会撞服务端连接数限制，表现是**大面积超时** → 全判成 `net_error` → 报告里一大片「可疑」，全是噪声 | ⚠️ **无 UI** |
| 探测节奏 | 360 / 1440 / 10080 分钟（6h / 每天 / 每周） | 面板可选，含「关闭」档 | ✅ |
| 切片预算 | 20000 ms/片 | MV3 SW 空闲 30 秒即被回收 | ✅ |
| 改址建议 | **只对同站给「采纳替换」** | 跨站一律标「需人工判断」：品牌改名与跳登录页从 URL 上无法区分 | ✅ |

**为什么是「距上次成功 ≥24h」而不是「最近 3 次」**：
`chrome.alarms` 官方文档写明它 "may delay them an arbitrary amount more"
（[官方文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)）——
丢一轮时，后者的语义是错的。

**「从来没成功打开过」不算死链**：那不叫「已经死了」，叫「还没探明白」。
否则你刚收藏一条拼错的 URL，它就会被建议替换。

## 3. 语义去重

| 阈值 | 值 | 判据 | 状态 |
|---|---|---|---|
| `semanticThreshold` | **0.92** | D6 拍板的**保守档初值** | 🔴 **未校准 —— 至今没有一次真实数据验证** |
| embedding 批大小 | 10 | 百炼官方硬限制，超了是 400 | ✅ 厂商给定 |
| 输入长度 | 标题 + URL + 正文摘要 **300 字**，总长 ≤1200 | `buildEmbeddingText` | ⚠️ 见下 |
| 向量维度 | 1024 | `text-embedding-v4` | ⚠️ **换模型/维度后必须清缓存**，否则新旧向量混在一起比 |

**校准方案见 [`semantic-calibration.md`](semantic-calibration.md)。** 摘要：

- 判据是**零误合并**，不是「找出最优阈值」——
  判成重复的代价（用户失去真收藏的内容）远高于漏判。
- 阈值 = 所有标为「不是同一份内容」的对里**分数最高的那一个**。
- 负样本**必须从真实数据按分数分带挖**，手写的负样本几乎必然是废的。
- ⚠️ **URL 被拼进了 embedding 文本**，会把镜像站的分数往下拉。
  如果校准显示正样本普遍偏低，第一个该试的是把 URL 去掉。
- 校准有可能得出「这个功能不该开」的结论，**那也是有效结果**。

| 阈值 | 值 | 判据 | 状态 |
|---|---|---|---|
| vendor 产物大小 | **< 800 KB** | `tests/unit/vendor-path.test.js` | ✅ 当前 601.4 KB |
| 含 `@anthropic-ai/sdk` 后的增量 | +215 KB | 接入 MiniMax 时带进来的 | ⚠️ **再加一家 T2 供应商前先读 `src/ai/vendor-entry.js` 顶部** |
| 命中率 | ≥70% | 打坏字典必须掉到 0 | ✅ |
| 面板对比度 | `contrast_gate.py` | 前景/背景比值 | ✅ 亚秒级，已接进 `precommit.py --all` |
| 面板 DOM 契约 | `ui_contract_gate.py` | E2E 靠数行数/按下标读字段的隐式耦合 | ✅ 亚秒级，接在 `verify_all.py` 第 0 步 |
| 隐私 | `privacy_gate.py` | 扫所有将推送的 blob，查真 key / **真实书签数据** | ✅ 仓库是 public |

**800 KB 这条红线的性质与其他不同**：它不是「别变大」，而是
**「再加一家 T2 供应商（Anthropic / Google）之前，先处理 `*.lazy.js` 里
那个动态 `import()` 被 esbuild 内联的问题」**。那要求改的是「单文件」这个前提本身，
不是把红线抬高一格。整套架构（mtime 契约 + 打包断言）都建在这个前提上。

## 6. 改动阈值时的纪律

1. 阈值本体写在**代码**里（`src/storage.js` 的 `DEFAULT_SETTINGS` 是设置项的权威），
   本表是**解释**，不是第二份权威。两边不一致时以代码为准，并回来修这张表。
2. 改任何一条**判据**（不是数值）都要**双向证伪**，见
   [`testing.md`](testing.md) 的「放宽判据要双向证伪」。
3. 面板上展示某个阈值时，应同时说明它**是否已校准**——
   「界面承诺一件永远不会发生的事，比功能缺失更伤」（`AGENTS.md` 第 8 条）。
