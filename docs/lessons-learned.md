# 踩坑记录（已修，留档）

从 `README.md` 拆出来。这些坑留档的理由统一是：**症状极具误导性**——
大部分表现为「某个功能就是不工作」，而根因在完全另一个地方。

改代码前不必通读。**症状对得上时再回来查**，按症状 Ctrl+F。

> 三张表的分法是「错误发生在哪一层」：
> 产品代码 → 测试代码 → 工具链与本机环境。
> 第二张最值得读，因为那类错误让闸门「因为错误的原因」而绿。

## 1. 产品代码里的 bug

| 坑 | 症状 | 根因 |
|---|---|---|
| `mutateMany` 回调收到的是 `{key:value}` **映射**，不是单个值 | 落盘对象多出一个嵌套的 `task:current`，`plan` 被重建成 `{items:[]}`，**执行器只搬第一条就停** | `{ ...(cur \|\| {}) }` 把映射整个摊平了 |
| `persistItem` 展开计划项本身 | 状态永远不推进，反复搬同一条，死循环 | 计划项此刻 `status` 还是 `'pending'`，把 extra 里的 `'done'` 覆盖回去了 |
| 路径模型不一致 | 幂等完全失效（每次都重排），且执行一条都搬不动 | `toPath` 不含根名但 `fromPath` 含；`ensureTargetFolder` 拿 `开发与技术` 当根 **id** 去 `getChildren()` |
| `backup.js` 的 `rootIdOf` 返回根**名** | 回滚对根级书签**全部静默失败**（不报错，就是没归位） | `chrome.bookmarks` 只认 id（`'1'`/`'2'`/`'3'`），且根名随界面语言变，不能硬编码 |
| `backup.js` 里 `parentId: '2'` 裸字面量 | 暂时看不出症状，但根 id 解析规则被绕过 | 同文件就有 `rootIdFromName`，硬编码等于把刚修好的规则又破一次 |
| 快照索引的读-改-写跨了锁 | 并发备份时索引互相覆盖，**列表里只剩一条** | `get → 算 → set` 三次独立进出 `serialize()`，中间能被别人插队 |
| 快照 `ts` 从 `new Date().toString()` 抽数字 | 同一秒点两次备份，后一次整个覆盖前一份 | 那是**秒级**精度的本地化字符串，天然会撞；同毫秒内去重要在临界区里做 |
| 去重清单的 `path` 退化成 `['2']` | 恢复出来的重复项**静默落进书签栏** | 把根 **id** 当成根名丢给 `rootIdFromName`，匹配不到就回落到书签栏 —— 不报错 |
| 根名兜底里比对中文字面量 | 英文 Chrome 上根名反查永远失败 | 根标题是**本地化**的，拿「其他书签」四个字去比必然不中，只能按 id 契约回落 |
| `startExecution` 里 `await run()` | 进度条从头到尾空白 | `sendMessage` 的响应要等整批跑完才回来 |
| 中断判定靠时间戳 | 浏览器重开后「继续」按钮永远不出现 | 「5 秒没刷新就算陈旧」不可靠，重开只要 2~4 秒就落在阈值内 → 改用 **SW 探针**（问它「真有循环在跑吗」，消息会唤醒 SW，新实例答 false） |
| **LLM 注入的 key 永远读不到** | 面板一直报「没有 API key」，但用户明明跑过 `inject_key.py`、文件就在磁盘上。**LLM 兜底一次都没跑过**，未分类条目全部落进「其他/待归类」 | `inject_key.py` 写 `src/llm-key.local.js`，而 `src/classify/llm.js` 里写 `import('./llm-key.local.js')` —— 相对 `src/classify/` 解析，指向**不存在的目录**。再叠上 `.catch(() => ({}))` 把加载失败整个吞掉，于是「读不到」和「没注入」报同一句话 |
| `fetch` 没有任何超时 | 网络不通时面板永久停在「LLM 兜底分类中…」：计划表空、**「执行整理」按钮一直禁用**，用户点它等于点空气 | LLM 兜底是 **await 在 `loadAndClassify` 里**的，而它是面板所有交互的入口。一次挂住的连接就冻结整个面板 |
| `loadAndClassify` 的调用点没有 try/catch | 改判后计划表**静默停在旧数据**上、也不报错；用户接着点执行整理 → 书签被搬到**旧分类**里去 | 改判/锁定/否决/恢复都直接 `await loadAndClassify(...)`，读树或 LLM 一抛错，界面就停在不一致的中间态。兜底层坏了不该有能力拖垮主流程 |
| `render()` 不 await 异步渲染 | 执行报告停在旧数字上（任务早已 100% 完成，面板还显示「成功移动 0 / 10」） | `render()` 里的 `renderSnapshots/renderCounts/renderReport` 全是「发射后不管」，而**面板上的数字就是用户判断有没有成功的唯一依据** |
| **面板从不说明「归入位置」** | 「归入位置」是其他书签时，45 条书签全搬到其他书签下的类目文件夹里，原文件夹被搬空但**仍留在书签栏**——书签栏看上去「一点没变」，面板还弹「整理完成」。用户只能靠猜 | 根归到哪由 `settings.targetRoot` 决定，而计划里的 `toPath` **不含根名**（见 `README.md` 的路径模型）—— 同一份清单在两个设置下产出完全一样，界面上也看不出区别。确认弹窗与完成提示都必须点名根名 |
| 启动被拒时仍提示「已开始执行」 | 点「执行整理」后毫无反应，也没报错 | 后端拒绝启动时返回的是 `{ok:true, result:{started:false, reason}}` —— `ok` 只代表消息送达了。UI 只判 `res.ok`，于是「已在执行中 / 计划为空」都被当成启动成功 |
| 全军覆没时仍提示「整理完成」 | 一条都没搬成，却弹「整理完成」，用户更困惑 | `status=done` 只说明**循环跑完了**，不代表每条都搬成功。失败明细还只藏在「设置 → 执行报告」里，而用户点完执行整理的视线在书签栏和计划表上 |
| **失败日志的「重新导出」按钮永远点不动** | 整理确实失败了，面板上也有失败横幅，但「重新导出」是灰的 —— 用户要刷新面板才发现能点 | 按钮的可用状态**只在 `init()` 刷过一次**，而失败记录是**执行时**才产生的。刷新点挂错了地方：异步产生的状态，刷新必须挂在**该状态产生的位置**（这里是 `renderReport()`），不能只挂在启动。现在计数与状态探测拆开：计数每次渲染都刷（纯 storage 读），状态探测只在打开面板/点刷新时做（要等网络超时，不能进轮询） |
| 端口占用判定的方向写反 | E2E 第一跑就报「端口已被占用」，而实际端口空着 —— 闸门变成永远红的摆设 | 判「资源是否可用」和判「操作是否失败」方向相反：**连得上 = 被占，连不上（ECONNREFUSED）= 空着**。`portBusy` 一开始把 `error` 事件当成了「占用」 |
| **`move()` 后从不回读** | 面板报 100% 成功、失败数 0，书签栏却一点没变，**全程无任何报错** | `chrome.bookmarks.move()` **resolve 只代表请求被受理**。有 `bookmarks` 权限的广告拦截器 / 书签整理类扩展会在书签变更时自动重排（不提示不留痕）、Chrome 同步会覆盖、用户自己会拖动 —— 改动被改回去后执行器一无所知。现每条 move 后立刻 `get()` 回读校验，代价是每条 29.3ms → 36.6ms |
| **计划里的书签 id 全部失效** | 45 条**全部**报 `Error: Can't find bookmark for id.`，而书签都还在树上 | 计划是从一棵**已经不存在的树**算出来的：书签删过又重建、恢复过备份、同步落地过，旧 id 全部失效。早先不校验就硬搬，于是 45 条逐条撞同一句墙。现执行前按 URL 重新定位到活着的节点；一条都对不上则**拒绝启动**并提示重新预览 |
| Chrome 的错误原话直接透传给用户 | 45 条一模一样的英文，用户既不知道是哪条、也不知道该查什么 | 探针实测（`tests/e2e/probe-errid.js`）：Chrome 对**三种不同故障**只有三句话 —— `Can't find bookmark for id.`(源 id 不存在) / `Can't find parent bookmark for id.`(目标文件夹不存在) / `Bookmark id is invalid.`(id 非数字)。不翻译等于零信息量 |
| 复用了用户已有的同名文件夹，却记成「我们建的」 | 回滚时按 `createdFolders` 清理空文件夹，会 `removeTree` **用户自己建的文件夹**（连带里面的书签） | `ensureTargetFolder` 早先无条件把文件夹 id 记进 `createdOut`，不区分「新建」与「复用已有」。改成只在 `ensureFolder` 返回 `created:true` 时记一次 |
| **归档队列里的正文按钮一直归档 0 条** | 面板永远显示「已归档 0/800」，按钮看上去一切正常 | 队列条目只有 `{url, bytes, at}`（有意不落 80MB 正文），而消费者读的是 `e.html` —— 恒为 `''`，每条都撞上「没有正文 → skipped」。**一个承诺了归档、实际归档 0 条的按钮，比没有这个按钮更伤。** 改正文在归档时重抓；详见 `src/archive/run.js` 顶部 |
| **归档文件名用进程随机化的 `hash()`** | 重启后文件名全变，`/text?url=` 找不到旧档，归档正文与向量缓存对不上 | 字符串 hash 每进程随机加盐。改用跨进程稳定的哈希（`tools/archive_sink.py --selftest` 的判据之一就是「文件名跨进程稳定」） |
| **暂停后闹钟抹掉队列** | 暂停一轮 → 等定时闹钟响一次 → 队列没了，面板显示「扫完了」 | 闹钟落到 `else` 分支去 `startRound([])`，而它是**建新一轮**（整体替换 entries/ids/cursor/total）而不是续跑。空数组 = 整条队列归零 |
| **三处 `storage` 读-改-写漏在临界区外**（2026-10-06 交接评审） | 双击「立即检测」或闹钟与面板重叠 → 中间那批书签**从未被探测**而面板显示「扫完了」；或在探测途中点「暂停」，暂停被旧快照整份写回而静默撤销 | `get → 改 → set` 三次独立进出串行链，而**读与写之间隔着整段网络**。改成「网络在临界区之外跑完 → 压成 delta → 进 `mutate` 基于当前值累加」，游标类状态再加一道「当前值仍是我出发时看到的值」的守卫。见 `AGENTS.md` 第 2 条与 `src/scan/runner.js` 的 `advanceCursor` |
| **`semanticThreshold` 没传到 `suggestMerges`** | 面板上的阈值滑块改不动任何一条建议 | 编排层调用时漏了 `threshold` 选项，函数退回硬编码的 0.92。功能「正常」，只是那个控件没有连上 |
| **`onPayload` 给 Anthropic 协议注入 `response_format`** | 每次调用先白吃一个 400，降级路径能通但每次都多一次失败 | `response_format` 是 OpenAI 兼容接口的字段，Anthropic 请求体里没有。加 `resolveJsonMode` 在发出去之前按协议关掉 |
| **界面承诺「逐条确认后亲自执行」** | 那个步骤永远不发生 | 「采纳替换」按钮早已被删，提示文案没跟着改。**界面承诺一件永远不会发生的事，比功能缺失更伤** —— 用户会据此安排自己的工作 |

## 2. 测试代码里的 bug（更值得记，因为它们让闸门「因为错误的原因」而绿）

| 坑 | 症状 | 根因 |
|---|---|---|
| E2E 只等按钮出现 | 点击丢失，**dry-run 零写入因「什么都没发生」而假绿** | `#btnPreview` 在 HTML 解析时就存在，那时模块还没跑、监听器还没绑 → 加 `body[data-ready]` |
| 等预览结果的条件不唯一 | 随机读到上一轮的旧数据 | 「表格有行**或**空态可见」在 `init()` 之后恒成立 → 改用单调递增的 `previewSeq` |
| `/已完成\|失败\|已暂停/` 匹配报告全文 | 幂等用例在只搬了 4 条时就断言「二次应为 0」 | **报告里永远有一行标签就叫「失败」**，匹配到的是标签不是状态 → 读 `#reportStatus` 单元格的值 |
| 等终态的判据本来就成立 | 续跑用例点「继续」前状态已是终态，等待立即返回 | 「已暂停」本身是终态 → 先显式等「执行中」证明续跑真的启动了 |
| `page.waitForFunction` 传异步谓词 | 报「执行没有产生任何进度」 | Playwright 对 Promise 返回值的真值判断不可靠 → 改成 Node 侧显式轮询 |
| 证伪脚本注入的符号不是真实导出 | 报「这道闸门是摆设」 | 模块直接 SyntaxError，加载失败 ≠ 闸门触发 |
| 证伪脚本过滤掉文件级失败 | 同上 | `not ok N - xxx.test.js` 也是红，早先被判成「没红」 |
| **单测把 bug 固化成了期望** | 报「keySource 应为 none」——而真相是注入的 key 根本读不到 | 断言写死 `keySource === 'none'`，恰好只在 import 路径坏掉时成立。换台机器、bug 修好之后，这条「一直绿的闸门」反而变红。判据必须**由文件系统推导**：文件在就必须读得到 |
| 静态闸门不去注释，匹配到「记录旧坑」的注释 | 报「仍有 `.catch(() => ({}))`」，可实现里根本没有 | 注释里常**故意引用出错的旧写法**来留档。`stripComments` 已从 `tests/helpers/sourceScan.js` 导出，各闸门统一复用，别再各写一份。⚠️ 若判据要**按行**查豁免标记，得用保行号的版本（`blankCommentsKeepLines`）—— 块注释被压成一个空格会让行号整体前移，且**不会报错**，只让闸门因为错误的原因而红或绿 |
| 判据写成「所有候选路径都必须能解析」 | 为一条**故意留的次选路径**报红 | 次选路径是留给将来挪目录用的，现在解析不到是正常的。强求「全部可解析」只会让闸门变噪声 —— 该钉的是「首个候选能读到」 |
| 编码闸门只收 `.js/.mjs/.json` | 它自己坏了一个字节却报「编码通过」 | 收集范围漏了文件类型。**闸门的覆盖范围要显式钉住**：范围之外的东西在闸门眼里等于不存在 |
| 干预测判焊死 `30s` 字面量 | 把超时改成 45s 这种正当改动会让测试红 | 判据钉的是**措辞/常量**而不是**性质**。这类红是误报，而误报的闸门比没有闸门更糟（大家只会学会忽略它，真违规也一起被忽略） |
| **`reachability` 查的是「名字出现过」不是「被调用过」** | 删掉调用点只留一行 `import { foo }`，18 条相关单测一条没红 | 闸门匹配的是 import 语句。关键逻辑要**额外**断言调用，判据找 `foo(` —— **括号是关键**，裸名字匹配会再次栽在 import 上。范例见 `provider-registry.test.js` 的「runtime.js 真的调用了 resolveJsonMode」 |
| **判据只认自己写样本时的形状** | `getMany([K.A, K.B])` 的解构形状 100% 漏检；`getXxx()` 取读包装写成单行就认不出来 | 判据必须对准**真实代码里出现过的形状**，而不是对准写样本时的形状。漏检和恒真在后果上是一回事：闸门看起来在，其实在这一整类上是空的 |

前三条都是同一类错误：**闸门匹配了一个本来就成立的状态**。
一条从没因为真实缺陷红过的闸门，和没有闸门是一样的。

> 放宽任何判据都要**双向证伪**（`AGENTS.md` 有完整表格）：
> 「该红」那侧容易糊弄——坏改动确实更坏，它自然会红；
> **「该绿」那侧才是判据的真正考验**。
> 记不住时问一句：**这条判据防的失效变了吗，还是只是措辞变了？**

## 3. 工具链与本机环境

| 坑 | 症状 | 根因 |
|---|---|---|
| 字典 `R()` 位置参数错位 | 只有部分标题匹配不到，像「规则写得不好」 | 混用 4/5 参数布局，pathWords 落进 domainSuffixes、titleWords 落进 pathWords |
| 字典里混入非法域名 | 那些域名永远不命中，静默失效 | 中文品牌名误放进 `domains` |
| 同一域名被多条规则声明 | 后面的全是死条目，部分悄悄归错类 | 匹配是首个命中即返回 |
| `github.io` / `google.com` 子域判定 | 会把合法拆分判成冲突 | 试图用「同一主域」去重子域 —— 这是坏闸门，已删并记录原因 |
| 扫描器漏副作用导入 | `import './apply.js'` 绕过零写入闸门 | 正则只匹配了带 `from` 的形式 |
| 扫描器用 `[^;\n]*?` 不跨行 | `import {\n applyPlan,\n} from './apply.js'` **整类绕过** | 导入子句本来就允许换行，禁掉换行等于给闸门留了一整类洞 |
| 扫描器不先去注释 | JSDoc 里的 `{import('./x.js')}` 被当真导入 | 闸门会因为**错误的原因**而红，大家只会学会忽略它 |
| 动态 `import('./apply.js')` 没被扫 | 写操作入口从闸门底下钻过去 | 作用域和时机由运行时决定，闸门没法证明它安全 |
| 能力闸门不去字符串 | 面板文案里**提到** `chrome.alarms` 之类 API 名，闸门对着说明性文字报红 | 同 `stripComments`，另有 `stripStrings`。⚠️ 只在能力闸门用 —— import 的模块说明符本身就是字符串，剥掉就什么都扫不到了 |
| 归一化剥掉全部 hash | SPA 的两个不同路由被判成重复 → 误删书签 | 过度归一化。`example.com/#/settings` 与 `#/profile` 是两个页面 |
| `selectForLlm` 选错集合 | LLM 兜底从来没生效过 | 兜底条目也在 `plan.items` 里，被「不在计划中」筛掉了 |
| 控制台是 GBK | 中文/emoji 全乱码，测试脚本自身崩在 `print` | `sys.stdout.reconfigure(encoding='utf-8')`（Python）/ `$env:PYTHONIOENCODING='utf-8'`（PowerShell） |
