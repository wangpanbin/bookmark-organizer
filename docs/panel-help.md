# 面板使用说明

面板的「帮助」页签在运行时读的就是这份文件（`ui/options.js` 的 `loadHelp()`）。

- 渲染只认一个 Markdown 子集：`#`~`###` 标题、无序/有序列表、段落、``` 代码块、
  行内代码、**粗体**、`[文字](https://链接)`、`---`
- **不要写表格**，当前渲染器不支持；**不要写引用块**，它会被当成普通段落
- 列表项可以折行写，缩进的续行会留在同一个列表项里

界面上的说明只保留三类：结论、状态、以及涉及信任边界的披露。其余都在这里。

---

## 计划明细

点「读取并预览」：扩展读一遍书签树，给出分类方案，**一条都不改**。
逐条核对无误再点「执行整理」。

左侧窄栏的六行是本次预览的结果：

- 已在位：已经在正确位置上的书签数
- 本次将移动：这一轮要动的条数
- 未分类：规则没命中、落进「待归类」的条数
- 重复项：可以合并的重复条数
- 将新建文件夹：这一轮会创建的目标文件夹数

顶部的进度脊线表示「已在位 / 书签总数」。它回答的是整理的**累计**进展，
不是这一次执行了多少；单次执行的进度是窄栏底部的进度条。

### 这一轮动的是哪些书签

执行按钮上方有一枚范围芯片，它只有两种取值：

- 「本次是全量整理」：整棵书签树里能动的书签都会被分类
- 「本次只整理清单里的书签」：只有「手动整理」页清单里的那些会动

两个入口（全量预览 / 预览选中）写的是同一份计划。这枚芯片存在的唯一原因，
就是让用户在点「执行整理」之前能看清范围 —— 它对应 2026-10-05 那次事故：
范围没显示清楚，45 条书签被整树重排。

### 为什么没有自动替换按钮

链接健康只给建议，扩展**永远不会自动改书签**。同站改址会把新地址摆出来，
可以直接点开或复制；死链可以查存档快照与候选地址。改不改、换成哪条，你自己动手。

曾经有过一个「自动替换」按钮，它登记一条全仓库没人读的提案，
toast 还承诺「到计划明细预览确认后才会执行」——而界面上没有任何确认步骤。
界面承诺一件永远不会发生的事，比功能缺失更伤。

## 重复项

只合并**完全相同**的地址。归一化只剥「纯顶部锚点」白名单里的 hash，
SPA 路由（`#/a` 与 `#/b`）一律保留，不会把同一个应用的几个页面判成重复。

删除不可逆，但可以通过「备份快照」页找回。每一条都可以单独勾「不删」，
勾上的条目不会进删除清单 —— 重复项是在「计划明细」页点「执行整理」时一起提交的，
这一步在计划明细页一次完成，不是逐条过。

## 手动整理

只整理清单里的书签。清单之外的不会被移动，也不会被删除。

流程：选择书签 → 加入清单 → 预览选中 → 核对 → 执行整理。
真正动书签的只有最后那一步。

清单页**每一行都会写明「将要归到 XXX」**，可以就在那一行的下拉里改。
改判只对这一次整理生效，不会变成规则影响以后。

勾选一个文件夹时，它里面的书签会在那一刻展开成一张快照，
之后文件夹变不变都不影响这张清单。移不动的条目（移动设备书签、已锁定、
浏览器内部页）会灰掉并写明原因。

### 没归类的条目会挡住执行

规则和 AI 都没判出分类的书签，会停在「其他 / 待归类」。这类条目**不会**被
悄悄处理掉：只要清单里还有它们，「执行整理」就是禁用的，页面上会有一块
说明写着还剩几条。

你有两个出路，都算数：

- 逐条在下拉里选一个分类
- 点「全部放待归类」，承认它们就该留在这儿

「一键重试未归类」是第三个选项：它让 AI 再判一次，但这次要求它给每一条都
选出最接近的一个分类。这样至少有了归属，代价是**有可能猜错**，所以结果
在行内标成「这是 AI 的猜测」，随时能改。

它只重发「AI 说不知道」的条目，不会重发上次请求失败的条目。

### 七种状态

待整理 / 已整理 / 已在原位 / 未归类 / 失败 / 已失效 / 无法处理。

其中**「已在原位」和「未归类」是两件相反的事**：前者是整理好了，
后者是压根没整理。执行完之后不会剩下「待整理」，每一条都有归宿。

## 链接健康

定时访问你书签里的那些 URL，读它们的 HTTP 状态码、跳转目标与页面头部信息。
**不会向任何第三方上传你的书签数据，也永远不会写入你的书签。**

完整的出网范围与去向在面板的「检测会发出哪些请求？」里，与授权按钮放在一起。

死链「AI 找新地址」开启后，会把**死链的标题与地址**发给你配置的模型服务商，
让它猜新地址。它没有联网能力，猜出来的东西必须逐个探测验证才会展示。
存档快照的查询不经过模型。

### 语义去重

判断「不同 URL 但同内容」：镜像站、转载站、官方文档与它的镜像。
启用后会把标题（以及归档出来的正文摘要）发到百炼做向量化。

结果只是建议，永远不会自动删除任何书签。

### 内容归档

把抓到的正文存到你本机磁盘，防链接腐烂。

扩展无法写任意本地路径，所以这一步需要一个本机进程在跑：

```bash
python tools/archive_sink.py
```

全部页面都存 HTML；面板里打上星标的页面会额外渲染成 PDF 和整页截图。
正文会在你点按钮的那一刻重新抓一次，所以已经打不开的页会如实报「重新抓取失败」。

接收器离线时面板**不会假装存了** —— 归档是「防链接腐烂」的全部价值所在，
静默失败比明确报错更糟。

## 设置

### LLM 兜底

规则没命中、落进「待归类」的那一小撮才会发给模型，不会外发整个书签列表。
没配 key 时自动跳过，不影响其余整理。

默认服务商 DeepSeek，预设里还有阿里云百炼、Moonshot Kimi、OpenAI。

**key 从哪来。** 直接填在面板的 API Key 输入框里，保存后存在本机
`chrome.storage.local`，不会离开这台机器。

也可以由本机环境变量注入一次，之后输入框留空即可 —— 这一条面向的是
自己装这份扩展的人，面板上不做说明。

模型名变动较频繁（`deepseek-chat` 已公告弃用），官方文档对「当前该用
哪个名字」说法也不一致。若报 400/404，换一个预设模型即可。

### 移动失败日志

书签没搬成时，把原因记到本机 `F:\logs\bookmark-organizer\`，按天一个 `.jsonl`
（一行一条，方便 grep 或喂脚本）。

扩展没法直接写本地磁盘，所以要先在本机开一个接收器。
接收器没开时不报错、不打断整理，失败记录会存在扩展里，
随时可以用面板上的「重新导出」手动存一份。

### 人工干预

锁定按 URL 记录，不是按节点 id，所以移动过位置也不会失效。

## 备份快照

每次预览和执行前都会自动存一份。Chrome 没有原生撤销，**这里是唯一退路**。

「恢复最近一份」恢复的是**整棵书签树**，不是某一次执行的回滚 ——
手动整理期间你自己在 Chrome 里做的其他归类，回滚时会被一并撤销。

## 已知问题

- 归档 `--dir` 有 bug：接收器 spawn 时不传环境变量，落盘位置永远回落到 `F:\archive`。
- 链接健康的超时与并发没有界面，要改得编辑 storage（8000ms / 6）。
- 语义去重的阈值 0.92 未经真实数据校准。
- 手动整理的回滚仍然是全树的。
- 「链接健康 / 内容归档 / 语义去重」三块面板没有 E2E 覆盖。
